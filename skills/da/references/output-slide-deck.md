# Mode-Report Sub-Reference — Slide Deck / Editable PPTX

> Loaded from `mode-report.md` when the chosen output format is a **presented deck** or an **editable
> PPTX / Google-Slides handoff**. The rest of the report library renders scrolling HTML; this file is the
> output channel for when the deliverable must be *shown live at the front of a room* or *handed off as a
> file the stakeholder edits*.

A slide deck is not "another report" — it is a **projection** of an analysis whose content already exists
(or is built per `mode-report.md` Step 5 storyline). This reference covers (1) when to project into a deck,
(2) the deck-authoring contract that survives an editable-PPTX export, (3) how to map any report archetype
into slides, and (4) the two export paths and when to use each.

## 1. When to project into a deck

| Want | Channel |
|---|---|
| Reader scrolls / explores on their own | Scrolling HTML report (the rest of the library) — NOT this file |
| You present it live, one message per slide | Slide deck (this file) |
| Stakeholder opens the file and **edits** it in PowerPoint / Google Slides | Editable PPTX export (this file, §4) |

If the deliverable is read alone at a desk, it is a report, not a deck. Don't force a scrolling report into
slides, and don't ship a deck where a 1-page exec read would do.

## 2. Deck-authoring contract (the part that makes the export editable)

Author the deck as **static HTML slides** on a fixed canvas (e.g. 1920x1080), one `<section>` per slide.
These rules are what make a clean **editable** PPTX (native text boxes + tables) instead of a pile of flat
screenshots — follow them whether or not you export today:

1. **One message per slide.** The title is the takeaway (action title), not the topic. Read the titles
   alone in sequence and the whole argument is legible (horizontal-logic test). This is the slide-level form
   of the `[Q][A][Why]` storyline in `mode-report.md` Step 5 — reuse it; only `[A]` becomes the slide title.
2. **Type floor: nothing a reader reads below ~24px.** Back-of-room legibility is the hard constraint, not
   page density. Dense tables stay at the floor and **split across slides** rather than shrink.
3. **Real `<table>` for tabular data.** `<table>/<th>/<td>` export as native, editable PPTX tables; a
   `display:grid` "table" does not.
4. **Static HTML slide bodies — no script-generated slide DOM.** Each text fragment in its own leaf element;
   repeated rows written out, not generated by a JS loop. This makes every text box map 1:1 to an editable
   PPTX text box AND keeps the source directly editable.
5. **Capture-safe CSS.** Meaningful content must be a real DOM text node. Do NOT carry meaning in
   `::before`/`::after` content text, `background-clip:text` gradients, `backdrop-filter`, `clip-path` masks,
   rotated / transformed text, or text baked into SVG / canvas. Decorative pseudo-elements are fine (dropped
   on export with no loss). Text fills must be solid colors (PPTX has no text gradient).
6. **No AI-tell glyphs in text runs** (same ban as every stakeholder output): no arrow glyph, em-dash, `≈`,
   `===`, `-----`. Per-chart takeaway renders `Nhận định: …`.
7. **Entrance animation end-state = the base style.** Animate FROM hidden; never ship a slide whose resting
   state is `opacity:0` — the PPTX capture, the PDF / print, and reduced-motion would all render a blank
   pre-frame.
8. **Charts: the sanctioned set only** (line, sorted bar, waterfall, delta-flat band) + diagram components
   (swimlane / RACI / mapping table). Banned charts stay banned (`references/storytelling-with-data.md`).
   Diagram flow / series color is a data-viz series, never a second UI accent.

**Fork, don't freestyle:** start from your house deck skeleton (a `deck-stage`-style HTML template), swap
data only. <organization>: `references/org-extensions.md` names the concrete A12 template + house skin.

## 3. Project a report archetype into a deck

The deck is the *form*; the source analysis supplies the *content* and which atoms come along. Rule of thumb:
**a report section that can't be said in one slide is two slides, not one dense slide.**

| Source analysis | Deck shape (slides) | Carry / drop |
|---|---|---|
| Deep-dive (WHY) | title · SCQR · anchor · one slide per driver · projection · recs · ask (~12-16) | carry anchor, verdict, comparator, waterfall |
| Ops dashboard | KPI summary · driver-table slide · 2-3 chart slides · actions | carry stat cards + verdict; drop sidebar / scroll-spy |
| Editorial paper | hero story · dense layers condensed (one per slide or a summary table) · projection · close | condense the layer block; keep verdict + comparator |
| Exec one-pager | BLUF · 2 anchors · 1 chart · directive recs (3-5 slides) | tightest; the cover / ask bookends carry it |
| Idea verification | hypothesis · assumptions · transparent math · sensitivity · Go / No-go | NO NSM / verdict / waterfall atoms |
| Training | objectives · concept grids · worked examples · check · recap | teaching density; NO NSM / verdict atoms |
| Data-quality | profile summary · severity-sorted issues · missingness · fit verdict | status ramp only; NO NSM / waterfall |
| Projection | method · scenario slides · confidence framing · band hero | carry the delta-flat band; verdict only if backtested |

Bookends: the title slide (thesis sentence = the one-line ask) and the summary / ask slide get the same
full-bleed treatment. Narrative arc for a proposal: problem, objective, solution, feasibility, ask.

## 4. Export — two paths (pick by environment + need)

The deck HTML is the **present-live** artifact on its own. To hand off an **editable** file, export it. There
are two exporters with **different contracts** — they are NOT interchangeable:

### Path A — `gen_pptx` editable mode (claude.ai / Claude cowork)
The hosted slides exporter. Input = the single `deck-stage` HTML above (multi-`<section>`, 1920x1080). Output
= editable PPTX with native text boxes + tables, fonts intact in Google Slides. **Preserves the full deck
form** (1920x1080, brand fonts, real tables, diagram components). Follow the export contract in your A12
template's `DESIGN-SPEC.md` §5b verbatim (mode / width / height, `resetTransformSelector`, per-slide
`goTo(N)` capture, `googleFontImports`, optional speaker-notes JSON).
- **Not a Claude Code CLI tool.** `gen_pptx` exists only in the claude.ai / cowork runtime. Do NOT call it
  locally; if you are in CC-CLI and the user wants the editable file here, use Path B.

### Path B — `pptx` skill, `html2pptx.js` (Claude Code CLI)
The local Node exporter (pptxgenjs + playwright + sharp), invoked via the `pptx` skill. **Different authoring
contract:** one HTML FILE PER SLIDE at 720x405pt (16:9), text only inside `<p>/<h1>-<h6>/<ul>/<ol>`,
**web-safe fonts only**, `<div>` becomes a shape, `class="placeholder"` for charts, no CSS gradients
(pre-rasterize to PNG). So a CC-CLI editable export means authoring to **this** shape, not feeding the
deck-stage deck 1:1. The deck DISCIPLINE (one message / slide, action titles, real tables, >=24px,
capture-safe) carries over; the HTML geometry does not.

**Decision note:**
- Present live + want the full brand deck + editable handoff with house fonts: author the `deck-stage` deck,
  export via Path A in cowork.
- Need a `.pptx` produced **here in Claude Code**, web-safe fonts acceptable: invoke the `pptx` skill and
  build to the Path B per-slide contract.
- Don't make `html2pptx.js` consume a `deck-stage` deck, and don't call `gen_pptx` from CC-CLI — that
  mismatch is the time-sink.

## 5. Definition of Done (a deck)
- [ ] Action titles throughout; titles-in-sequence tell the whole story.
- [ ] One message per slide; nothing a reader reads < ~24px; no wall of text.
- [ ] Tabular data in real `<table>`; charts from the sanctioned set; single accent (series color is not a
      second accent).
- [ ] No AI-tell glyphs; per-chart takeaway as `Nhận định: …`; full diacritics on stakeholder text.
- [ ] Entrance end-state = base style (print / PDF / reduced-motion show the finished slide).
- [ ] If exported: opens as **editable** PPTX (native text / tables), fonts intact — not flat screenshots.
